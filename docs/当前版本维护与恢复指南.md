## 一、恢复工作时先看这里

无论是新的 Codex 任务、对话被压缩，还是换电脑继续维护，都按下面顺序开始：

1. 打开本目录 `杰哥工具5.1-苹果风`，不要修改保留的旧版 `杰哥工具5.0`。
2. 阅读根目录 `AGENTS.md`。
3. 阅读本指南链接的最新交接快照和 `docs/杰哥工具5.1-开发入口.md`；9月7日排版说明仅在追溯初版时读取，不当成当前状态。
4. 需要追溯完整业务规则时，阅读 `docs/杰哥工具4.0-需求归档.md`。
5. 恢复时先核对源码版本、用户本次目标及最近验收；有新代码改动时运行 `node --test tests/*.test.js`，不为只读状态询问重复整轮浏览器检查。
6. 代码修改后运行全部测试，并用浏览器实际操作受影响页面；纯文档变更核对路径和状态一致性即可。

把这几步交给新的维护任务，即可恢复当前工作状态，不需要重复发送此前的大量截图和聊天记录。

## 四、仍需人工确认的项目

`1200×600mm` 鎏金小板目前缺少经过确认的托盘长、宽、高。系统可以核算重量、包装数量和 DB，但顺心捷达体积重与最终运费必须继续提示人工询价。没有新权威数据前不得猜测或静默套用其它托盘尺寸。

海洞石、洞石拼接在历史开单公共规则与重量页存在重量口径差异。此前明确要求保留洞石资料，本轮未改其规格、价格和单品重量规则；发货前须人工核对，不应直接把两处数值视为一致。具体差异见整体检查报告。

价格表有产品但重量原表没有可确认对应关系的项目（例如花岗岩拼接、平板、马赛克）不再套泛关键词重量；开单提示人工填写。

## 五、交付与上传

每次完成修改后：

1. 更新首页版本号、上传说明、开发入口和需求归档。
2. 运行全部回归与实际浏览器检查。
3. 提供完整源文件夹，保留 `index.html`、`README-上传说明.txt`、`AGENTS.md`、`tools/`、`tests/`、`docs/`。
4. 核对文件夹内资源完整，不再创建ZIP、RAR、7z等压缩包；除非用户后续明确重新要求。
5. 保留5.0旧版最近一版及现有历史文件夹，不擅自删除。历史文档中“保留ZIP/必须打包”的旧约定已被本次用户要求取代。

## 六、长任务防丢失建议

- 已确认的业务规则必须写入需求归档，不只留在聊天中。
- 每个独立功能完成后更新本指南顶部的版本、当前事项、待办和验收链接；恢复只加载当前摘要，历史细节按需查。
- 长步骤前或准备换任务时，在 `docs/checkpoints/` 新增带时间的交接快照，不覆盖旧快照；只记录已完成/未完成/决策/边界/验证证据，不复制整段聊天和截图。
- 所有历史需求必须区分“已完成”和“当前待办”；不能看到旧截图就再次重做，样式以最新确认决定为准。
- 搜索先定位文件/函数，再读取有限片段。不要整段输出包含Base64水印的HTML，测试只返回失败详情及汇总；避免对同一结果反复检查。
- 一个大功能完成并整理好完整文件夹后，可以开启新任务继续；新任务只需提供本目录位置并要求先读本指南。
- 不要在一次消息里重复上传全部历史截图；只提供本次新增问题的截图和明确规则。
- 切换任务须用户明确要求；不会自动新建、关闭、清空聊天，也不擅改模型窗口或自动压缩配置。
- 当前5.1目录尚未被父目录Git跟踪；交接说明并非源码备份，不能依靠空的 `git diff` 判断已经保存到版本历史。禁止自动 reset/clean，提交或远端备份另按用户授权执行。
